Change Risk Scoring Engine

Auditable change risk scoring on 8 weighted dimensions with inherent vs. residual modeling from ISO 31000. CAB-ready narrative on a local LLM. No data leaves the machine.

The Problem

  • Every CAB struggles with the same question: "How risky is this change?" Standard changes get pre-approved, but non-standard changes sit in a grey zone where the risk level isn't obvious until someone reads the details.
  • Most tools slap a generic Low/Medium/High label on everything, from a risky database migration to a minor feature flag change, without any reasoning or a path to track how the risk drops as the team applies mitigations.
  • Past incident data exists in a separate system. Reviewers rarely cross-reference it, even when a similar change caused an incident last quarter. The institutional memory is in people's heads, not in the scoring process.
  • The result: inconsistent risk levels across reviewers, no structured way to explain the score, and no revision trail showing how mitigations changed the picture.

The Approach

  • Context-aware analysis: reads the change request in plain English rather than forcing users into a rigid, fixed checklist
  • Dynamic weighted scoring on 8 key factors including potential breakage, rollback plans, deployment timing, and security exposure. Rule-based, auditable, no black box.
  • RAG retrieval via FAISS vector search over past change requests. Surfaces similar changes and their outcomes automatically.
  • Audit-ready tracking: inherent risk (before mitigation) and residual risk (after mitigation) across revisions, using the same risk language compliance teams use every day (ISO 31000)
  • Explainable AI: a local Ollama LLM generates a concise narrative explaining exactly why it assigned the score. Template fallback if Ollama is unavailable.
  • Scalable architecture: currently running as a proof-of-concept on a local LLM, the design is built to scale into private enterprise clouds like AWS Bedrock or Azure OpenAI

The Impact

  • Seconds, not hours: structured scoring replaces subjective manual review
  • Inherent 3.11 HIGH → Residual 1.72 LOW across two revisions, with the report explaining exactly what changed and why
  • 100% on-premise: no data sent to external APIs, built for PCI DSS / SOX / FFIEC environments
  • 131 pytest tests, Python 3.12, works without Ollama or FAISS installed
  • Audit-ready output: structured Markdown report with decision band, score gauge, dimension table, and revision history
