Incident Pattern Analyzer

Clusters incident postmortems by similarity, surfaces the recurring root causes that get re-discovered every quarter, and points to runbooks that already address each cluster. Built for SRE and ops leaders who need to turn 60+ incidents per quarter into actionable themes.

Python 3.12 LangChain FAISS Ollama 21 tests Vector clustering
·· The Problem

Every quarter the team rediscovers the same root cause.

Incident postmortems generate rich data, but most teams treat each incident as a one-off. Recurring root causes get re-discovered every quarter instead of surfaced as patterns.

  • ● The same timeout misconfigured across services
  • ● The same on-call gap, every Friday night
  • ● The same config drift, every release
  • ● No connection from "we should write a runbook" to "the runbook already exists"
·· The Solution

Cluster, retrieve, narrate. Local LLM throughout.

A Python tool that ingests incident records, embeds them via vector search, clusters by similarity, and produces a runbook-aware narrative explaining recurring patterns and which existing runbooks address each cluster.

  • ● FAISS vector clustering of incident records
  • ● Runbook RAG retrieval for each cluster
  • ● AI-narrated theme summary per cluster
  • ● All processing local on Ollama
·· The Impact

Patterns that one-at-a-time review can't see.

·· Why this matters

Postmortems are written. Themes are not.

Most engineering organizations have postmortem discipline at the individual incident level. Very few do thematic analysis across a quarter or a year. The recurring patterns hide in plain sight. This tool surfaces them with vector clustering and runbook-aware narration, then leaves the action prioritization to the human reviewer.
