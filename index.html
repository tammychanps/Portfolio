Case 01 · Change Risk · Python · 131 tests · 2026

Change Risk Scoring Engine

Context. Every production change at a bank goes through a CAB. Analysts manually review each request, cross-reference past incidents, and write risk assessments. 30 to 60 minutes per change with significant variance between reviewers.

Action. An auditable change risk scoring tool that scores each change on 8 weighted risk dimensions, retrieves similar past changes via vector search, and generates a CAB-ready risk narrative on an on-premise LLM. Models inherent vs residual risk so addressed mitigations are tracked across revisions.

Outcome. Replaces 30 to 60 minutes of manual review with a CAB-ready report in under a minute. Inherent vs residual model gives reviewers a clear before/after as mitigations land. All processing local. Designed for PCI DSS, SOX, and FFIEC environments.

Case 02 · Operational Resilience · Python · 21 tests · 2026

Incident Pattern Analyzer

Context. Incident postmortems generate rich data, but most teams treat each incident as a one-off. Recurring root causes get re-discovered every quarter instead of surfaced as patterns.

Action. An operational resilience tool that ingests incident records, embeds them via vector search, clusters by similarity, and produces a runbook-aware narrative explaining recurring patterns and which existing runbooks address each cluster.

Outcome. Surfaces recurring pain points invisible to one-incident-at-a-time review. Runbook awareness means recommendations point to existing tooling, not just "you should write a runbook." On-premise LLM, no data leaves the machine.

Case 03 · Stakeholder Reporting · Python · 21 tests · 2026

Program Status Report Generator

Context. Senior leaders ask for weekly program status reports synthesizing Jira items, project charters, and recent activity into a one-page summary. PMs spend 2 to 4 hours per week on this and the output is uneven across PMs.

Action. A stakeholder-aware reporting tool that ingests a Jira export and a project charter, generates a structured weekly report with status, risks, top tasks, and a narrative summary on an on-premise LLM. Templated where it can be, AI-narrated where prose is needed. Audit trail preserved end-to-end.

Outcome. 2 to 4 hours of weekly status writing collapsed into a generated draft a PM edits in 15 minutes. Local LLM means it works in environments where cloud AI is forbidden.

§ 03 · Build List

What I'm thinking about building next.

Five candidates ordered by where they land in the program lifecycle. All universal TPM tools. None of them exist on anyone else's GitHub yet.

  1. Cross-team dependency mapper. Reads Jira exports, draws the dependency graph, surfaces the critical-path bottlenecks that kill program timelines.
  2. Roadmap reality check. Compares stated commitments against velocity and dependency data, generates a confidence score for each milestone before the exec has to ask.
  3. Pre-mortem question generator. Input a project plan. Output the top ten questions a smart pessimist would ask before kickoff, so the risks get surfaced while there's still time to mitigate them.
  4. Sprint goal drift detector. Every Friday reads the sprint board, compares to the sprint goal, flags tickets that don't ladder up so scope creep gets caught mid-sprint instead of mid-quarter.
  5. Postmortem quality scorer. Reads an incident postmortem, scores it on completeness covering root cause, contributing factors, action items, and blameless tone, suggests what's missing.
